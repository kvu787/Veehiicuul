## Assistant

**`partial` lets your code and Godot’s generated code become one class.**

In C#, a class marked `partial` can have its definition spread across multiple source files. The compiler combines those parts into a single type. [C# documentation](https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/classes-and-structs/partial-classes-and-methods)

Godot uses this during the build: its **source generators** inspect your class and generate additional members that connect it to the engine, including support for method calls, properties, and signals. This keeps that mechanical integration code out of your `Main.cs`.

Conceptually, with both declarations in the same namespace:

```csharp
// Main.cs — written by you
public partial class Main : Node {
    public override void _Ready() {
        GD.Print("Meow");
    }
}

// Another source file — generated by Godot (schematic)
public partial class Main {
    // Additional engine integration members.
}
```

The result is **one `Main` class containing both sets of members**. Combining the parts happens at compile time, so `partial` itself adds no runtime overhead.

**If you remove `partial`, the build fails with Godot error `GD0001`.** Your `Main` inherits from `Node`, which inherits from `GodotObject`; Godot requires these classes to be partial so its generators can extend them. Suppressing the diagnostic leaves the class without required generated integration and can cause runtime errors. [Godot documentation](https://docs.godotengine.org/en/stable/tutorials/scripting/c_sharp/diagnostics/GD0001.html)

Ordinary helper classes that do not inherit from `GodotObject` generally do not need `partial`.
